# 集中治療科ホームページ（沖縄県立中部病院）

プロジェクト名（ブランド）: **集中治療の、今**（フッターに小さく表記。ページタイトルは「集中治療科」のまま）

## 目的

1. 一般の方向けに、当院集中治療科の理念・治療対象を紹介する
2. レジデント・フェローのリクルートのため、仕事内容を詳しく紹介する

この2つの目的を1つのページに混在させず、**役割の異なる2ページ構成**にしている。

## サイト構成

| ファイル | 対象 | 内容 |
|---|---|---|
| `index.html` | 一般向け（患者さん・ご家族） | 診療内容／診療理念／対象疾患／設備紹介／スタッフ紹介／CTA（受診・面会の問い合わせ） |
| `recruit.html` | レジデント・フェロー向け（採用） | スケジュール／数字で見るICU／教育体制／修練医の声／現場からの発信／CTA（研修・見学の問い合わせ＋紹介リンク発行）／患者さん・ご家族向けページへのクロスリンク |
| `style.css` | 共通CSS | 両ページで共有。CSSカスタムプロパティで配色を切り替え |
| `script.js` | 共通JS | 両ページで共有。スムーズスクロール、アクティブナビ、スクロールリビール、紹介リンク機能 |
| `media/echo-handling.mp4` | 動画素材 | 「現場からの発信」に掲載中の試し撮り動画（実データ） |
| `media/resident-avatar-{1,2,3}.png` | イラスト素材 | 「修練医の声」のアバター3枚（256×256、背景透過） |
| `media/src/` | 元素材 | 書き出し前の原本置き場。**サイトからは参照されない**（切り出し直し用。詳細は `media/src/README.md`） |
| `robots.txt` | 検索避け | サイト全体をクロール禁止に設定 |

両ページとも相対パスのみで組んであるため、**フォルダごとコピーすればどこにでも移設できる**（GitHub Pages・院内サーバーいずれも可）。

### 運営管理会社への引き渡しについて

完成後、ファイル一式を病院の運営管理会社へ渡して正式サーバーに載せてもらう方針。引き渡し時の注意点:

- **HTMLファイル単体では表示が崩れる。** `index.html` / `recruit.html` は `style.css` と `script.js` を外部参照しているため、**上表のファイルをフォルダ構造ごと**渡すこと（`media/` の中身も含む）
- 逆に、`README.md` `HANDOFF.md` `media/src/` は**制作側の内部メモ・素材置き場**なので、渡さなくてよい（渡しても害はない）
- **取得方法**: リポジトリの「Code」→「Download ZIP」、または `git clone`。いずれも常に最新の公開内容と一致する
- **`<meta name="robots" content="noindex, nofollow">`（`recruit.html` / `index.html` の `<head>`）と `robots.txt` は、正式公開のタイミングで外すこと。** 外し忘れると検索エンジンに一切載らない
- **CSS/JSの参照には `?v=YYYYMMDD` を付けている**（例: `style.css?v=20260915e`）。ブラウザキャッシュ対策で、CSS・JSを更新したらこの値も更新する運用。移管先でも同じ運用を続けてもらう
- **引き渡し前に解消しておくべき項目**は下記「まだ決まっていないこと・今後の課題」を参照。CTA・フッターのリンク先は 2026-09-15 にすべて確定済み（下記「CTAのリンク先」「フッター『関連リンク』」）。**リンク先未設定のボタン・リンクは残っていない**

### ⚠️ 実名・住所の暫定公開について（要対応・優先度高）

現在、GitHub Pages上に医師・看護師の実名や病院住所が掲載されているが、**この暫定公開自体について病院として正式な許可プロセスを通していない**（診療科長など内輪の合意のみ）。2026-07-14 時点の合意事項:

- **目標**: 2026年9月末（次の専攻医・フェロー採用選考シーズン開始前）までに、病院サーバーへの正式移行許可を取得する
- **それまでの暫定対応**: 紹介リンク発行機能（在籍医師がURLを第三者へ意図的に配布する機能）は、能動的にURL・実名情報の拡散範囲を広げてしまうため、**正式許可が下りるまで一時的に無効化・非表示にする** → **対応済み**。`script.js` 冒頭の `REFERRAL_ENABLED = false` が唯一の制御点で、再開時はここを `true` に戻す
- 新たに実名・顔写真を伴うコンテンツ（後述のスタッフ他己紹介・イベント紹介など）を追加する場合も、**原稿・写真の準備は今から進めてよいが、実際の公開は正式許可が下りてから**という運用にする

判読不能だったが、二重の安全策として加工した。
